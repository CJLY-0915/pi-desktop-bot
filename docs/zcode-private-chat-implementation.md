# ZCode 私聊能力对齐：本次实现与边界

范围为各渠道单机器人连接和私聊，支持飞书、Telegram 等不同渠道同时启用。没有新增 Lark、同渠道多机器人实例、群聊或话题功能；钉钉接入 UI 继续保持“即将支持”。实施前的官方源码对照保存在 `zcode-capability-gap-analysis.md`，不能把其中的旧差距表当作本次实现后的状态。

## 手机操作

- 普通问答：Agent 调用 `ask_phone` 后，在手机点击选项或回复编号；多选回复 `1,2`，也可直接输入自定义文字。`/取消提问` 结束等待。回答进入原工具，不创建新 prompt。
- 提问默认最多等待 10 分钟。插件重载或断开后请求失效，Agent 得到明确错误，需要重新提问，不会自动采用默认选项。
- `/重试`：补发最近失败消息或本轮保存结果。平台超时可能已经送达，重试可能出现重复；没有“严格一次投递”的保证。
- `/定时 每隔 30 检查项目状态`：每隔 30 分钟执行。允许 5–10080 整数分钟。
- `/定时 每天 09:00 汇总待办`：按本机本地时区每天执行。
- `/定时 列表`、`/定时 暂停 <id>`、`/定时 恢复 <id>`、`/定时 删除 <id>`；`/cron` 为同一入口。

日程每个私聊最多 20 项，PI-Desktop 与插件须保持运行。重启跳过错过的执行；会话忙碌或派发失败时记录失败，不堆积、不自动重执行。暂停或删除不撤销已经被宿主接受的运行。解绑、更换授权或切换关联会话后旧日程不能继续派发，需要删除后重新创建。

## 已核实的宿主限制

本机已安装宿主包为 0.21.0；通过只读检查 `app.asar` 与 Agent runtime 核实，未修改宿主，也未读取真实会话正文或凭据。

1. 插件没有公开的原生工具权限请求列表或请求事件。`tool/resolvePermission` 虽公开，但为 dangerous，仍会弹出桌面原生确认。逐工具授权继续在桌面处理，不能用手机业务问答代替。
2. 原生 `asktool` 没有公开请求发现入口；本次用独立的 `ask_phone` 等待手机回答。远程轮次调用原生 asktool 时会得到使用新工具的引导，不声称接管了原生卡片。
3. `plans/resolve` 和 `session/configure` 也仍受宿主桌面原生确认约束。手机选择只是提交请求，不能绕过桌面确认。
4. 宿主日程只公开 `scheduled/list`，没有公开创建、修改、删除和运行归属接口。本次日程由插件管理，不同步宿主定时页，不猜测宿主已有日程的结果收件人。
5. 正式图片是否被内联送入模型取决于宿主和模型视觉能力；SVG 作为文件。音频、视频作为文件上下文，没有新增语音转写服务或保证模型直接理解音频。
6. `native-pi:` 会话不支持这里使用的正式附件与扩展工具，不承诺上述完整交互。
7. 文件行数仅来自本轮被观察到的 Edit/Write；Shell 或外部程序改动不自动统计。超过 2 MiB、二进制或差异计算预算的文件省略行数。并发外部修改无法归因到单次工具。
8. 不回放绑定前的历史，不自动补投插件完全离线期间未记录的新轮次。已有待结束轮次可恢复；完成内容超出本地读取或保存上限时可能截断，不能承诺无限长度结果全文。
9. 消息不保证带 `turnId`，公开接口不能按宿主 turnId 反查输入消息 ID。执行中切入以已观察到的扩展 runId 接收后续输出；宿主先结束时最多等待 3 秒接收该扩展最终正文。扩展正文和确切快照边界均不可用时，明确提示「回复同步失败」，不把读取失败改写成任务执行失败，也不猜取最近的历史回复。

宿主还存在独立的 RACP 协议，具有自己的身份与角色授权。本次没有接入它，没有读取私有身份文件或绕过插件确认边界。

## 验证范围

使用现有 Node 测试、真实本地临时文件、回环 IPC 和注入平台 HTTP 完成验证；临时文件与日志放在本次 PI scratch。另运行 PluginCheck，使用浏览器操作控制面板的重试入口及约 390px 窄屏布局。

没有向真实飞书、微信、Telegram 聊天发送验收消息，也没有在真实手机客户端验证 Card 2.0 的最终像素效果。卡片的原生横线、顺序、展开/折叠、toolCallId 去重、恢复与预算通过结构和行为测试验证；浏览器面板检查不能替代平台端到端验收。
